# Contributing

Thanks for helping with this project.

## Before you start
- Check if the work already has an issue.
- Make sure the issue has a milestone.
- Add labels that match the work.
- If there is no issue, create one first.

## Branch flow
- Never work directly on `main`.
- Create a branch before you edit files.
- Keep the branch name short and clear.

Examples:
- `docs/readme-blueprint`
- `feat/launcher-search`
- `fix/overlay-resume`

## Pull request flow
- Open a PR when the work is ready.
- Link the issue in the PR.
- Use closing words when the PR should close an issue.
  - Example: `Closes #42`
- Add the right labels to the PR.
- Keep the PR summary simple.

## Good PR structure
Use this order:
1. What changed
2. Why it changed
3. Tests run
4. Screenshots or clips, if useful
5. Linked issue

## Writing style
- Use plain language.
- Keep the tone helpful and direct.
- Avoid unnecessary jargon.
- Use short bullets when possible.
